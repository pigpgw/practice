# 반도체와 메모리 — 테라다인 업무의 뼈대

코딩 문제 04번(ASCII) 뒤, 05번(로그 파싱) 전에 보는 곳이다.
테라다인 FAE 면접에서 반드시 나온다는 질문들이 여기 모여 있다.

---

## 1. 공정 흐름 — 웨이퍼부터 패키지까지

```
웨이퍼(한 장의 실리콘) → 다이(die, 웨이퍼 위의 네모) → 패키징 → 보드 장착
```

- **웨이퍼**: 거대한 실리콘 웨이퍼. 수백~수천 개의 다이(칩)이 나란히 있다.
- **다이**: 웨이퍼 위 한 칩. 이걸 잘라서(핑) 패키지로 보낸다.
- **패키징**: 다이 encapsulation + 리드. 메모리는 BGA, NAND는 TSOP/CBGA 같은 패키지.

"칩 문제"인지 "테스트 문제"인지 말할 때 이 단계부터 본다.

## 2. 웨이퍼 테스트 vs 파이널 테스트

| | 웨이퍼 테스트 | 파이널 테스트 |
|---|---|---|
| 시점 | 패키징 **전** | 패키징 **후** |
| 대상 | 웨이퍼 위의 다이 | 완성된 칩 |
| 장비 | **프로버(prober)** — 바늘로 다이 접촉 | **핸들러(handler)** — 칩을 소켓에 자동 장착 |
| 불량 처리 | **리페어(RA)** 후 재검사 가능 | **수리 불가 → 폐기** |
| 수율 | 공정 수율 반영 | 최종 수율 반영 |

"웨이퍼 테스트에서 RA로 살렸는데 파이널에서 떨어졌다"는 이슈가 실제로 일어난다.
어느 단계에서 죽었는지가 원인 추정의 출발점이다.

**백엔드/포어버**: 필러(wafer) 위에 다이 하나씩 찍는 탐침 장비. "풀오버"로 발음될 수
있지만 정식 용어는 **prober**다.

## 3. 테스트 프로그램 — PASS / FAIL / Bin

DUT(검사 대상)에 전기적 자극을 인가하고 응답을 측정한다. 기대값(Low/High)과 비교해
**PASS / FAIL**을 내고, 더 나아가 **Bin 번호**로 분류한다. Bin 1 = 합격, Bin 5 = 어떤 조건
불량, 이런 식이다. 공정 쪽에서 "어느 Bin이 몰렸나" 보면 원인을 좁힌다.

**Site**: 여러 개 DUT을 동시에 검사하는 자리. 8 site 장비도 흔하다.

코딩 문제 14번(웨이퍼 집계), 25번(테스트 플랜/Bin 판정)이 이걸 데이터로 다루는 문제다.

## 4. RA — 리페어(리던던시)

불량 난 다이를 살리는 방법이 있다. **리던던시 회로**로 우회시켜서 다시 검사하는 걸
**리페어(Repair)**라고 하고, 이를 RA(Repair Assist)라고도 부른다.

- 대상: 한두 비트가 물리적으로 고장 난 셀. 여분(fuse) 회로를 태워 우회시킨다.
- **eFuse**: 한번 태우면 복구 안 되는 programmable fuse. DRAM/NAND 안에 여분을
  남겨두고 리페어에 쓴다.
- 리페어 성공 → PASS로 집계. 실패 → 패키징 공정에서 제외.

"불량이 난 건 리페어로 살릴 수 있나요?"라는 질문은 나올 수 있다.
코딩 문제 18번(리페어 전후 수율 비교)이 이 계산이다.

## 5. 휘발성 vs 비휘발성 (무조건 나오는 질문)

| | 휘발성 | 비휘발성 |
|---|---|---|
| 전원 차단 시 | 데이터 **사라짐** | **유지** |
| 계열 | RAM 계열 | ROM 계열 |
| 대표 | **DRAM** (요즘은 **HBM**도 한몫) | **Flash**, 그중 **NAND** (USB, SSD, SanDisk, Kioxia) |

면접용 한 줄로는 이렇게 정리된다.

> "휘발성은 RAM이고 그중 대표가 DRAM, 요즘은 HBM이 많이 언급됩니다.
> 비휘발성은 ROM이고 그중 대표가 플래시, 특히 NAND입니다."

## 6. DRAM 과 SRAM

| | DRAM | SRAM |
|---|---|---|
| 데이터 유지 | **주기적 리프레시 필요** | 전원 공급 시 유지 |
| 속도 | 느림 | 빠름 |
| 셀 면적·비용 | 작고 저렴 | 크고 비쌈 |
| 용도 | 시스템 메모리, GPU | 캐시 |

**왜 리프레시가 필요한가**: DRAM은 커패시터가 전하를 잃어버리니까, 정해진 주기(보통 64ms)에
전부 읽어 다시 써주는 리프레시가 필요하다.

## 7. DRAM 셀 — 1T1C

- 셀 하나는 **트랜지스터 1개 + 커패시터 1개(1T1C)**.
- 커패시터에 전하가 있으면 `1`, 없으면 `0`.
- 트랜지스터는 **스위치** 역할. 게이트(워드라인)에 전자를 인가하면 비트라인으로
  전하가 흘러 읽고 쓴다.
- **워드라인**: 행 선택. **비트라인**: 열 선택.
- 공정이 미세해질수록(3나노 → 2나노) 같은 면적에 더 많은 셀이 들어가서 용량이 늘어난다.

"메모리 셀이 어떻게 동작하는지" 설명하라는 질문의 정답이다.
면접에서 위 3~4문장으로 정리해 둔다.

## 8. HBM

- **High Bandwidth Memory**. DRAM 기반.
- 칩을 **TSV(실리콘 비아)**로 수직으로 쌓아(예: 8~12단) 한 패키지로 만든다.
- 넓은 인터페이스로 연결돼서 **대역폭이 매우 높다**. GPU/AI 가속기에 쓰인다.
- DRAM 기반이므로 **리프레시가 필요**하고, 전원 차단 시 데이터가 사라진다.

"HBM은 다른 DRAM과 뭐가 다른가요? 약자는?"는 실제 출제 질문이다.

## 9. NAND Flash

- **페이지 단위** 읽기/쓰기, **블록 단위** 삭제.
- 셀당 비트 수로 등급이 나뉜다: **SLC 1비트, MLC 2비트, TLC 3비트, QLC 4비트**.
- 셀이 많아질수록 밀도(용량)는 올라가지만 **수명과 성능은 불리**해진다.
- USB, SSD, SanDisk, Kioxia 제품.

## 10. Fault — 고장 유형

- **RAM fault**: stuck-at(항상 0 또는 1), transition(0→1 전이 실패),
  coupling(한 셀 변화가 옆 셀에 영향), address decoder fault
- **NAND fault**: stuck-at, decoder, transition, random(임의 셀)

실제 FAE는 FA(fail analysis) 장비로 어디가 깨졌는지 좁혀 간다.

## 11. ECC와 여분(Spare)

- DRAM: ECC(Error Correcting Code)로 비트 에러를 검출하고 교정.
- NAND: 여분 페이지(spare area)를 두고, ECC로 고칠 수 없으면 그 셀을 여분으로 대체하거나
  **리페어**로 우회시킨다.

"불량 비트를 여분으로 넘기는 게 리페어냐?"라는 질문의 연결고리다.
