# C++ 개념 — 시험 코드를 읽기 위한 최소 지식

코딩 문제 03·04번(디버깅)을 보기 전에 보는 곳이다.

> **Python만 준비하는데 C++를 왜 보냐?**
> 실제 시험지는 C++로 나왔고, 메모리 누수 디버깅 문제는 **C++ 코드를 고치는 문제**다.
> Python으로는 C++ 코드를 읽을 수 없다. 코드를 직접 짜는 게 아니라
> **"이 코드가 왜 틀렸는지"를 알아채는 것**이 목표다.
>
> 시험에서 Python을 선택해도, 면접관이 C++ 코드를 보여주며 "이것도 보세요?"라고
> 물어볼 가능성이 있다. 그때 최소한 읽기는 돼야 한다.

각 항목은 설명과 **Python 대응**을 같이 둔다.

---

## 1. new / delete — 단일 객체

```cpp
Node* p = new Node();   // 힙에 할당
// ... 사용 ...
delete p;               // 반드시 해제
```

- `new`는 **힙**에서 메모리를 잡는다. 스택이 아니다.
- `delete`를 안 하면 **누수(leak)**. 프로그램이 끝날 때까지 메모리가 돌아오지 않는다.
- `delete p`를 두 번 부르면(double free) → 프로그램이 죽는다.

**Python 대응**: Python엔 `new`/`delete`가 없다. 대신 `open()`을 안 닫으면 파일 핸들이
남고, 리스트에 계속 쌓으면 메모리가 늘어난다. → 코딩 문제 03·04번

## 2. new[] / delete[] — 동적 배열

```cpp
int* arr = new int[100];
// ... 사용 ...
delete[] arr;      // []가 들어가야 함
```

- `new[]`로 받으면 **`delete[]`**로 해제해야 한다. `delete`를 쓰면 안 된다.
- 실제로 `delete`를 써도 컴파일은 되지만 UB(정의되지 않은 동작)이다.
  배열의 각 원소 destructor가 호출되지 않아 잔해가 남는다.

친구가 실제로 시험에서 이걸로 틀렸다고 한다. `new`가 보이면 **반드시 `delete` 짝을
찾아라.** `new[]`면 `delete[]`여야 한다.

## 3. vector — 최신 C++ 방식

```cpp
std::vector<int> v;
v.push_back(10);          // 추가
int x = v[0];             // 접근
int n = static_cast<int>(v.size());
v.clear();                // 비우기
```

- **RAII**: vector가 메모리를 자동으로 해제한다. `delete`를 안 써도 된다.
- 크기를 미리 알면 `reserve()`로 미리 확보해 재할당을 줄인다.
- 범위 기반 for: `for (int x : v) { ... }`

시험에서 "최신 C++ 기법"을 선호한다고 분위기가 있었다고 한다.
`new[]`를 `vector`로 바꾸면 정답이라는 답이 자주 나온다.

## 4. RAII

**Resource Acquisition Is Initialization.** 자원(메모리, 파일, 잠금)을 얻는 시점에
객체를 만들고, 그 객체가 **소멸될 때 자원을 자동으로 반환**하는 패턴이다.

- `std::unique_ptr`, `std::lock_guard`, `std::ofstream`이 모두 이 방식이다.
- 예외가 나도 스택이 풀리면서 자원이 정리된다.

**Python 대응**: `with open(...) as f:`가 정확히 이 아이디어다. 블록이 끝나면 자동으로
닫히고, 예외가 나도 닫힌다. → 코딩 문제 01·05번처럼 파일을 다루는 모든 문제

## 5. std::string 와 std::stringstream

```cpp
std::string s = "hello";
std::stringstream ss(s);
std::string token;
while (std::getline(ss, token, ',')) {   // ','로 분리
    // token 처리
}
```

- `getline(ss, token, ',')` — 구분자 기준 분리. 로그 파싱 문제와 똑같다.
- `std::to_string(double)` — 숫자를 문자열로.
- `std::stod(s)` — 문자열을 double로.

주의할 점: `std::stod`는 잘못된 문자열이면 예외를 던진다. FAE가 실제로 본
"range 오류"가 이런 예외 미처리였다.

**Python 대응**: `line.split(",")`, `float(s)`.

## 6. ifstream / ofstream — 파일 입출력

```cpp
std::ifstream in("input.txt");
std::ofstream out("output.txt");
std::string line;
while (std::getline(in, line)) {
    out << line << "\n";
}
```

- `<<`로 출력, `>>`로 입력.
- **`>>`는 공백 단위로 읽으므로 줄 전체가 필요하면 `getline`**을 쓴다.
- 바이너리는 `std::ios::binary`를 붙인다. 안 붙이면 줄바꿈이 개행으로 변환된다.
- **경로**: 상대경로는 **Visual Studio의 작업 디렉터리 기준**이다. 여기서가 제일 흔한
  함정이다. 프로젝트 설정에서 작업 디렉터리를 바꾸거나, 소스 경로 기준으로 파일을 잡아야 한다.

실전 4번이 "input text를 C++로 읽고 output text로 저장"이었다. 파일 경로와 인코딩
(Windows는 cp949, Linux는 UTF-8) 차이가 실제 실패 원인이다.

**Python 대응**: `open(path, "r", encoding="utf-8")`. → 코딩 문제 01·05번

## 7. 정수형과 오버플로

| 타입 | 크기 | 범위 |
|---|---|---|
| `char` | 1바이트 | -128 ~ 127 (unsigned면 0~255) |
| `short` | 2바이트 | -32,768 ~ 32,767 |
| `int` | 4바이트 | -2,147,483,648 ~ 2,147,483,647 |
| `long long` | 8바이트 | ±9.2×10¹⁸ |
| `unsigned int` | 4바이트 | 0 ~ 4,294,967,295 |

- 부호 있는 정수는 **2의 보수** 표현이다.
- 범위를 넘으면 **UB(정의되지 않은 동작)**. 컴파일은 되지만 결과가 이상해진다.
- `0xFFFFFFFF`는 unsigned int의 최댓값이다. 부호 있는 int에 넣으면 -1이 된다.
- 비트 연산에는 `unsigned`를 쓰는 게 안전하다: `value &= 0xFFFFFFFFu;`

코딩 문제 06번(메모리 테스트 패턴)이 32비트 연산이다. `1 << 31` 같은 값은 int에서 음수가 된다.

**Python 대응**: Python 정수는 임의 정밀도라 오버플로가 없다. 대신 비트 연산 동작이
C++와 같으려면 `& 0xFFFFFFFF`로 마스킹해야 한다.

## 8. const, 참조, 포인터

```cpp
void print(const std::string& s);   // 복사 없이 넘기고, 안에서 못 바꾸게
const int* p = &x;                  // 가리키는 값을 못 바꾸게
int* const p = &x;                  // 포인터 자체를 못 바꾸게
```

- `const &`는 **복사 없이 전달 + 변경 방지**. 부를 때 복사 비용이 안 든다.
- `const`가 없으면 실수로 값을 바꿔 버릴 수 있다.

**Python 대응**: Python은 참조를 넘기는 게 아니라 **객체 참조**를 넘긴다. 불변은 관례로
처리한다.

## 9. 예외 처리

```cpp
try {
    int* p = new int[10];
    p[100] = 1;          // 범위 밖 접근 → 예외 가능
    delete[] p;
} catch (const std::exception& e) {
    std::cerr << "Error: " << e.what() << "\n";
}
```

- `try` / `catch` / `throw`.
- `catch (...)`로 모든 예외를 잡을 수도 있다.
- **`delete`가 `try` 안에만 있으면 예외 때 누수된다.** RAII로 바꾸는 게 정답이다.

실제 시험 3번의 "range 오류로 프로그램이 터졌다"가 이 상황이다.
그리고 `catch (...)`로 전부 삼키면 **오류를 조용히 넘겨버려** 결과 파일이 틀어진다.
→ 코딩 문제 03·04번의 오류 처리 규칙(stderr + 종료 코드 1)과 같은 함정이다.

**Python 대응**: `try/except`. `except: pass`는 오류를 조용히 삼키는 제일 나쁜 패턴이다.

## 10. STL — map, unordered_map, sort

```cpp
std::map<std::string, int> counts;        // 정렬된 키-값
counts["L01"] += 1;

std::vector<std::string> names;
std::sort(names.begin(), names.end());

std::unordered_map<std::string, int> fast;  // 정렬 안 됨, 평균 O(1)
```

- `map`은 키가 **정렬**돼서 순회하면 정렬된 순서다. `unordered_map`은 순서 보장이 없다.
- "첫 등장 순서"를 요구하는 문제는 `map`이 아니라 **삽입 순서를 유지하는 구조**가 필요하다.
  C++에서는 `vector<pair<>>`에 순서를 따로 저장해야 한다.

**Python 대응**: `dict`가 삽입 순서를 유지한다(3.7+). → 코딩 문제 07번(웨이퍼 집계)의 첫 등장 순서 유지

## 11. include 와 namespace

```cpp
#include <iostream>
#include <fstream>
#include <vector>
using namespace std;
```

- `#include <iostream>` — 표준 라이브러리 헤더. `<>`는 표준, `""`는 사용자 헤더.
- `using namespace std;` — `std::` 생략. 편하지만 권장되지는 않는다.

**Python 대응**: `import`와 비슷한 개념인데, Python은 표준 라이브러리가 기본 내장이라
대부분 import가 필요 없다.

## 12. Visual Studio 에서 C++ 돌리기

- 새 프로젝트 → **빈 프로젝트** → `.cpp` 파일 추가 → 빌드(Ctrl+Shift+B) → 실행(Ctrl+F5)
- **작업 디렉터리 확인이 핵심이다.** 프로젝트 속성 → 디버깅 → 작업 디렉터리.
  기본값이 `$(ProjectDir)`인데, 설정을 바꾸면 입출력 파일을 못 찾는다.
- 콘솔 프로젝트로 만들어야 `main`이 붙는다.
- 컴파일 옵션: `/W4`(경고), `/std:c++17` 등. `/EHsc`가 없으면 try/catch가 제대로 안 돈다.
- 인코딩: 소스 파일이 UTF-8이면 `/utf-8` 옵션.

**Python 대응**: 터미널에서 `python3 problem05.py`. 작업 디렉터리 개념은 같다.
